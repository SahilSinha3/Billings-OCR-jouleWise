⚡ End-to-End Query & Document Processing Lifecycle

From the moment a PDF or image is dropped into the frontend dropzone to the instant verified numbers render and export to CSV, here is the exact chronological path through every subsystem:

Stage 1: Ingress & Hashing < 1ms
Cryptographic SHA-256 Fingerprint
Next.js sends a multipart upload to FastAPI. The backend computes the raw byte SHA-256 digest immediately upon receiving the file stream.
backend/app/api/v1/endpoints/bills.py upload_bill()
Stage 2: Cache Lookup < 5ms
Sub-5ms Redis Deduplication
Checks Redis key bill:sha256:{hash}. If the document already exists, the full verified payload returns instantly, displaying an "Already Parsed" notification and opening the bill.
backend/app/services/cache/redis_client.py get_cached_bill()
Stage 3: Persistence < 10ms
Zero-Disk PostgreSQL BYTEA Storage
On a cache miss, the file bytes are stored directly as a PostgreSQL BYTEA binary blob. No files or slices are ever saved to the local hard disk.
backend/app/models/bill.py Bill(file_data=contents)
Stage 4: Async Dispatch < 1ms
In-Memory asyncio.Queue Dispatch
The bill ID is enqueued into an asynchronous worker queue. HTTP response returns HTTP 202 to the browser so the UI never times out on heavy multi-page documents.
backend/app/workers/queue.py task_queue.enqueue(bill_id)
Stage 5: OCR Engine ~2.2s
Poppler 200 DPI + Tesseract 5 LSTM
Poppler multi-threaded rasterizer converts pages to 200 DPI 8-bit grayscale images. Neural Tesseract OCR 5 runs in a single pass (--oem 1), extracting tokens and bounding boxes.
backend/app/services/ocr/engine.py DocumentOCREngine.extract()
Stage 6: Guardrail < 5ms
Non-Bill Classification Guardrail
Evaluates keyword density to detect non-bills (e.g. Schneider EM6400 register map/manual). Flags document as REJECTED_NON_BILL, storing clean null values rather than artificial zeroes.
backend/app/services/ocr/universal_extractor.py validate_is_electricity_bill()
Stage 7: Heuristic Parsing < 15ms
Multi-DISCOM Pattern Extractor
Extracts Consumer Name, Account Number, Bill Reference, Due Date, Active Energy, Power Factor, and Net Amount Due (e.g. JVVNL ₹585,217 right before "Rupees Only").
backend/app/services/ocr/universal_extractor.py extract_heuristic_fields()
Stage 8: Math Audit < 5ms
Deterministic Tariff Audit Engine
Audits meter delta consistency ((Curr - Prev) * MF = Consumed), Power Factor bounds (0.0 to 1.0), and date chronology. Marks status as VERIFIED with green badge.
backend/app/services/verification/engine.py MathVerificationEngine.verify()
Stage 9: Delivery & Export < 15ms
Live Dashboard & CSV Export
Frontend unblurs to show the verified metrics alongside the streaming PDF viewer. Users can download a full CSV export containing all 16 audited parameters.
backend/app/api/v1/endpoints/bills.py export_all_bills_csv()
🏛️ High-Level Design (HLD) Architecture

JouleWise employs a 5-tier architecture separating client presentation, stateless HTTP ingress, sub-5ms caching, relational storage, and an asynchronous worker pipeline:

1
Client Tier — Next.js 16 Pure CSS Modules
Apple-inspired monochrome light mode, screen-blurring loader shield, native embedded PDF viewer, and smart file input reuse handling.
Port 3000
2
Ingress Gateway — FastAPI Async HTTP Engine
Receives multipart uploads, generates cryptographic SHA-256 digests, serves database streaming endpoints, and generates CSV reports.
Port 8000
3
Cache Tier — Local Redis 7 In-Memory Store
Key-value store mapping SHA-256 hashes directly to verified JSON payloads. Enables sub-5ms lookups for pre-existing documents.
Port 6379
4
Persistence Tier — PostgreSQL 17 BYTEA Storage
Stores raw document binary blobs as BYTEA. Tracks bills, meter readings, line items, and audit reports without touching local disk.
Port 5432
5
Worker Tier — Decoupled Pipeline (Poppler + Tesseract + Verification)
In-memory asyncio.Queue worker running 200 DPI rasterization, neural Tesseract LSTM, regex heuristics, and tariff mathematical audits.
asyncio.Queue
⚙️ Low-Level Component Design (LLD)
1. OCR & Rasterization Engine
- Poppler: Renders PDF pages at 200 DPI with 4 parallel worker threads.
- Grayscale: Converts images to 8-bit single-channel arrays.
- Tesseract 5: Uses neural LSTM engine (--oem 1, --psm 6/11).
engine.pyDocumentOCREngine
2. Multi-DISCOM Parser
- APDCL: TOD register columns (Solar, Peak, Normal) summed to Total kWh.
- JVVNL: Net Payable Amount matched preceding Indian "Rupees Only".
- GESCOM: Dispatch reference CNL/AEE/SA/25-26/ & ordinal due date.
universal_extractor.pyextract_heuristic_fields
3. Non-Bill Guardrails
- Evaluates negative technical keywords (register map, consolidated register map, datasheet).
- Rejects non-bills immediately with REJECTED_NON_BILL.
- Sets all fields cleanly to null.
universal_extractor.pyvalidate_is_electricity_bill
4. Progressive Summarizer
- Decoupled from core OCR: verified metrics render immediately.
- Asynchronously queries Gemini 2.5 Flash or local Ollama (Llama 3.2).
- Instant deterministic template fallback if offline.
universal_extractor.pygenerate_bill_summary

📐 Mathematical Audit Formulation & Database Schema

Rule 1: Meter Register Consumption Reconciliation

Δ = Current_Reading - Previous_Reading
Calculated_Units = Δ × Multiplying_Factor
Audit Test: |Calculated_Units - Reported_Units| ≤ 1.0 kWh

Rule 2: Time-of-Day (TOD) Energy Summation

Total Active Energy = Solar_Units + Peak_Units + Normal_Units ± 1.0 kWh

Rule 3: Power Factor Physics Invariant

Physical Sanity Bound: 0.0 ≤ Power Factor ≤ 1.0 (or 0.0% ≤ PF ≤ 100.0%)

Rule 4: Date Chronology Invariant

Billing_Period_Start ≤ Billing_Period_End ≤ Bill_Issue_Date ≤ Payment_Due_Date
